# Product comparison

User approved implementation of the in-chat design. Customers select up to four whole products from one storefront category using card/PDP controls. Browser-local versioned storage remembers IDs, public names and category; no account sync is required. A compact tray provides removal, clear and compare access; navigation also exposes the comparison page. Selection never auto-navigates or opens the cart.

The compare API accepts at most four unique positive IDs and fetches only published products, with no outage/demo fallback in live mode. Return current prices, availability, images, brand, category, SKU and visible WooCommerce attributes. Shared taxonomy IDs match attributes across products; custom attributes match normalized names. Hidden attributes are not exposed. Dynamic rows automatically include newly populated attributes, omit all-empty rows and show Not specified for individual gaps. Values are compared without option order/case/whitespace noise. Whole-product option lists and starting prices are clearly distinguished from chosen variants. Weight and dimensions are included only when actual store units can be verified.

The page uses aligned semantic table columns, horizontal scroll on mobile, sticky specification labels, highlights differences on request, and product purchase/detail links. Deleted/private IDs remain removable. Failures preserve selection and offer retry. The tray is hidden on compare, cart and checkout and while a native dialog is open, and sits above PDP mobile purchase controls. Card hearts and gallery swipes retain their behavior. All action touch targets are 44px. Fit 320px with no document overflow.

Comparison storage contains public IDs/names/categories only; private selections are excluded from indexing and public Markdown/agent pages. No new plugin, dependency or database is needed. WooCommerce reads revalidate within 30 seconds and use existing product invalidation tags. Prepare a reviewed preview; production release is a separate instruction.
